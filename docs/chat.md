# Chat (chat.subsurfaces.net)

Realtime chatroom ("Philchat") on Supabase Realtime plus the Worker REST API. The REST contract for
third-party clients is [`../CHAT-API.md`](../CHAT-API.md); this file covers how the UI and backend fit
together. Outstanding work is in [`../ROADMAP.md`](../ROADMAP.md). Stonks/points were removed in 2026-07
(see `docs/migrations/2026-07-chat-denormalize.sql`); do not rebuild them from old specs.

## Shape

- `ChatShell` renders `ChatPage` for every path (catch-all route). `SideChat` is a thin wrapper around the same `ChatRoom` inside a frosted-glass panel docked to the right of the main site (draggable 260-600px, width persisted), with container queries for narrow layouts. BgCanvas shows through every chat container (`backdrop-filter`).
- `ChatRoom` is composed from hooks `useChatMessages` (history, realtime merge, optimistic send/react/delete with rollback), `useChatScroll`, `useChatToast`. Failures surface as toasts, never silently.
- **Identity is denormalised**: `messages` carries `username`/`name_color`/`avatar_url`, written at POST time and propagated on profile change, so realtime broadcasts are self-describing and clients must not re-fetch to enrich them. `profiles` is the fallback for pre-migration rows. Messages API returns newest first; the client reverses.
- Presence: Supabase Presence channel per room drives `TypingIndicator`; `/mute` stops broadcasting.

## Features

- **Rendering**: `src/lib/parseMessageBody.ts` tokenises text, `:emote:` (from `/emotes/index.json`, generated by prebuild from `public/emotes/`), markdown images (GIF picker), image URLs, YouTube (click-to-load thumbnail), Twitter/X link cards, plain links, footnote sidenotes. One embed per message, lazy-loaded via IntersectionObserver, `onError` hides broken images, emotes get an ephemeral canvas-sampled glow.
- **Input**: unified autocomplete (`:` emotes, `@` mentions, `/` commands), emote preview strip, emote picker with filter and a Klipy GIF picker (`/api/chat/gif-search`), replies, edit (up-arrow on an empty input edits your last message, `(edited)` marker), delete, reactions (emote picker in the hover actions).
- **Moderation**: admin pins (ticker bar above the list, auto-cycling), temporary/permanent bans (permanent hard-deletes content and anonymises the profile), room create/archive from the channel dropdown. Ban state is read from `profiles.ban_*` on writes.
- **Settings** (`ChatSettings`): name colour (`profiles.name_color`), density (compact/comfortable/spacious), font scale, terminal mode, API keys (`sk_...`, `/api/keys`).
- **Persona bots**: `POST /api/chat/command` (`debate`, `ask`/`chat`, `quote`, `yellowcard`, `tape`, `bothelp`) in `src/worker/chatBot.ts`, personas from `src/features/boot/chatbot.ts`, per-room debate cooldown, bot messages inserted under bot identities.

## Terminal mode

`>_` in QuickControls (chat shell only) toggles `chatTerminal` (persisted; `?terminal=1` forces it for the session). The
chat becomes a CLI frontend for the same API, deliberately isolated from the site's token cascade
(black background, IBM Plex Mono only, no blur, no glow).

- `TerminalBootScreen`: randomised BIOS elements, an ASCII PHILCHAT splash that waits for a key, then a message roll-in. Skippable at every phase (click, key, Esc); boot and chat views are mutually exclusive.
- `TerminalChatView`: `[user] body` lines, `↳` reply previews, reaction chips, `$` prompt, autocomplete for `/`, `@`, `:`, command history (last 20), rich rendering through `parseMessageBody`.
- Commands (see `COMMAND_DEFS` in `TerminalChatView.tsx` for the live list): `/help /me /shrug /clear /timestamps /reply /unread /room /whoami /users /mute /log /grep /watch /search /goto /react /edit /delete /pin /pinned /color /options /about /flip /mock /philquote /debate /ask /quote /tape /yellowcard /bothelp /boot /fastboot`, plus admin `/ban /unban /kick`.

## Realtime and auth notes

- Shared cookie auth (`VITE_COOKIE_DOMAIN=.subsurfaces.net`) means logging in on wiki also logs in chat; Supabase Auth redirect URLs must include every host plus `http://localhost:5173/**`.
- Realtime is enabled on `messages` and `reactions`; RLS: authenticated read, own insert, own reaction delete.
